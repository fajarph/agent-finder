# AgentFinder — Coding Agents & Multi-Agent Terminal Discovery

An educational machine-learning project. It **collects real public GitHub project metadata and README content**; it does not ship a fake training dataset.

## Requirements
- Windows PowerShell, Python **3.12** 64-bit, Node.js 20.19+ or 22.12+.
- Internet for GitHub repository discovery and initial npm/pip installs.
- Optional `GITHUB_TOKEN` with read-only access for higher GitHub API limits. **Do not use your TMDB token.** Do not commit any token.

## Recommended workflow
> **Shortcut — no Colab needed.** `data/` and `models/` are already committed (including the trained `.joblib` models, `metrics.json`, and the real crawled CSVs). Download the repo with **Code → Download ZIP**, extract it, and jump straight to step 3. Steps 1-2 are only for regenerating the dataset and models from scratch.

1. *(Optional)* To regenerate everything from scratch, open `notebooks/AgentFinder_Colab.ipynb` in Google Colab, run cells top to bottom, and export `AgentFinder_Artifacts.zip`. Extract it into the root `AgentFinder` folder and verify `models/knn.joblib` and `data/agents_clean.csv` exist.
2. *(Optional)* Or re-crawl and re-train locally — see "Crawling without Colab" below.
3. In VS Code, open `AgentFinder`, then open **two PowerShell terminals**:

**Terminal 1 — API** (run from project root):
```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install --only-binary=:all: -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn ml.service:app --host 127.0.0.1 --port 8000
```

**Terminal 2 — Frontend:**
```powershell
cd frontend
npm install
npm run dev
```
Open **http://127.0.0.1:5173** in browser. Keep both terminals open.

## Crawling without Colab
From the project root, after installing requirements:
```powershell
$env:GITHUB_TOKEN = "YOUR_READ_ONLY_GITHUB_TOKEN"  # optional; never paste into public screenshots
.\.venv\Scripts\python.exe -m ml.pipeline crawl --max-repos 100
.\.venv\Scripts\python.exe -m ml.pipeline train
```

## Data methodology and limitations
- Search GitHub repository API and GET public project README Markdown for automated collection.
- `data/agents_raw.csv`: collected repository documents; `data/crawling_log.csv`: download provenance; `data/label_audit.csv`: provisional category decisions; `data/agents_clean.csv`: selected dataset.
- **Classification labels are weak labels**, based on predeclared keywords in product descriptions / READMEs. They require human audit. Automated keyword labels can bias measured accuracy. Do not claim accuracy against verified expert labels.
- Model evaluation uses stratified holdout split and fits TF-IDF on training data only; recommenders fit the catalog for product similarity, without claiming classification accuracy.
- API data collection is not identical to HTML scraping. Check with your instructor whether automated API + public README document crawling satisfies the assignment. GitHub API use and copyright rules still apply.
- No tool's quality, price, compatibility, or capabilities are independently certified. Official repository links are displayed for inspection.
- `Precision@5` is intentionally **not** fabricated: it requires independently judged query→tool relevance labels, which are not provided.
- If insufficient valid labeled data exists, training **fails clearly** rather than fabricating examples.

## Presentation guide
1. Research question: how to recommend coding tools and classify tasks?
2. Dataset provenance: GitHub queries, README retrieval, collection timestamps, duplicates and audit.
3. Labels: weak-label heuristics and limitations.
4. Text preprocessing/TF-IDF: fit only on training partition for NB and DT.
5. NB / DT: same stratified train/test split; compare macro F1 and confusion matrices.
6. KNN: cosine distance over catalog TF-IDF; similarity not probability.
7. Demonstrate a real search and show repository links.
